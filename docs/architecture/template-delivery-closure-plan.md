# 模板交付闭环计划

## 目标

本阶段的目标不是继续扩能力，而是把当前模板仓库收敛为一套可初始化、可联调、可验收、可回归的正式模板工程。

完成后应满足：

- `backend` 继续作为唯一契约源稳定支撑消费端。
- `admin` 保持正式后台管理面，不再是本阶段阻塞项。
- `app` 与 `weapp` 都具备客户侧最小正式闭环，而不是演示骨架。
- 仓库具备明确的初始化、联调、验收、回归入口，任何执行者都能按文档跑通。

## 本阶段边界

本阶段正式纳入：

- `app`：客户侧 Web 前台正式闭环。
- `weapp`：客户侧小程序/H5 前台正式闭环。
- 模板交付文档：初始化、联调、验收、回归说明。
- 自动化回归：前台最小链路验收脚本。

本阶段明确不纳入：

- 新业务页面、新业务模块、新业务导航。
- `backend` 新增功能面。
- 多租户、消息通知、复杂工作流、字段级审计、业务型 dashboard。
- 任何仅用于展示模板能力的示例内容。

## 交付标准

### 消费端闭环

- `app` 与 `weapp` 都具备以下正式链路：
  - 登录
  - 会话恢复
  - 首页
  - 我的页
  - 账户安全或会话相关操作
  - 退出登录
  - 基础错误态与未登录引导
- 用户可见文案只描述真实能力，不出现模板宣传式表达。
- 不保留多余入口、假能力、平行接口定义或 demo 风格默认行为。

### 模板交付

- README 与 `docs/` 中有清晰的一条主线说明：
  - 如何初始化
  - 如何启动联调
  - 如何验收
  - 如何做回归
- 环境文件生成、数据库启动、契约校验、核心 UI 验收都有明确命令入口。

### 自动化回归

- `backend release` 继续作为后端正式 gate。
- `admin` 保持现有 UI 验收。
- `app` 增加最小正式闭环验收。
- `weapp` 至少具备可重复的构建/类型校验与手工验收清单；若本轮成本可控，则补自动化 H5 验收。

## 实施主线

### 一、消费端正式化

#### `app`

`app` 当前已有登录、首页、我的页、账户安全页和退出链路，本阶段重点不是重做，而是补正式模板交付所需的最小自动化验收，并确认页面表达与状态流转足够收敛。

本线任务：

- 校验登录到首页的主链路。
- 校验我的页、账户安全页和退出登录链路。
- 如自动化暴露出页面阻碍，再做最小修正。

#### `weapp`

`weapp` 当前仍偏骨架态，是本阶段的主要实现对象。

本线任务：

- 重做首页的信息结构，只保留真实高频入口和状态信息。
- 重做登录页，补齐默认校验、错误提示、会话已存在判断。
- 重做我的页，补齐登录状态、账户信息、退出登录与未登录引导。
- 补 `session` 恢复与统一会话工具，避免页面各自猜测状态。
- 清理宣传性文案和 demo 风格样式，统一到黑白灰中性基线。

### 二、模板交付文档化

本线任务：

- 补一份集中式交付文档，串起初始化、联调、验收、回归。
- 明确 `bootstrap / dev / smoke / check` 的职责。
- 明确环境文件、端口、数据库与契约生成物的关系。
- 给出失败排查和回归顺序，避免只能靠口头传递。

### 三、验收与回归固化

本线任务：

- 保留 `backend` 正式发布校验。
- 保留 `admin` UI 验收。
- 新增 `app` 最小闭环验收脚本与运行入口。
- 梳理 `weapp` 的手工验收步骤；若本轮实现成本可控，再补自动化。

## 执行顺序

1. 先补文档总计划，冻结本阶段目标与边界。
2. 并行推进：
   - `weapp` 正式闭环实现
   - `app` 最小验收自动化
   - 模板交付文档补齐
3. 接回根命令与 README，使脚本入口清晰。
4. 跑完整验收与回归。
5. 对照本计划逐项核验，确认是否达到收口条件。

## 验收清单

### 代码层

- `weapp` 不再保留模板宣传式首页或散装个人页。
- `app` 与 `weapp` 均只消费 `backend` 正式 customer 契约。
- 不新增无消费面的页面、菜单或演示逻辑。

### 自动化

- `pnpm run check:backend-release`
- `pnpm run smoke:admin:ui`
- `app` 最小闭环验收脚本
- `pnpm --filter weapp typecheck`
- `pnpm --filter weapp build:h5`
- `pnpm run check:template-delivery`

其中：

- `check:backend-release` 是后端正式发布 gate，不被消费端聚合脚本替代。
- `check:template-delivery` 是本阶段消费端交付聚合入口，串联 `admin` UI 验收、`app` UI 验收、`weapp` 类型校验与 H5 构建。

### 手工验收

- `app`
  - 登录成功
  - 首页状态正确
  - 我的页信息正确
  - 账户安全页可进入
  - 退出登录后回到登录页
- `weapp`
  - 打开后能识别登录/未登录状态
  - 登录成功后进入正式首页或我的页
  - 我的页展示真实账户信息
  - 退出登录后回到未登录状态

## 回归顺序

1. `backend` 发布校验
2. `admin` UI 验收
3. `app` 自动化验收
4. `weapp` 类型校验与 H5 构建
5. `weapp` 手工/半自动验收

若只需要重复执行消费端交付回归，可直接运行：

- `pnpm run check:template-delivery`

## 收口判定

只有同时满足以下条件，本阶段才算完成：

- 文档已能指导执行者独立完成初始化、联调、验收、回归。
- `app` 正式闭环有自动化保障。
- `weapp` 正式闭环已脱离 demo 骨架。
- 根命令与 README 没有出现平行入口、模糊职责或过时描述。
- 回归全部通过，工作区没有遗留半成品。
