# 模板实例仓库模型

本文档定义 `rtnn` 主线进入真实部署阶段后的实例职责模型，目标是把“模板源码”“私有实例目录”“部署引擎”三条线收敛成稳定结构，而不是继续靠口头约定推进。

当前推荐固定为三层结构：

- `rtnn`：开源模板源码仓库
- 私有实例目录：本地或私有仓库维护的真实实例工作区
- `rtnn-deploy`：开源部署引擎仓库

这三层共同组成模板工程进入真实部署阶段后的正式交付主线。

## 1. 为什么需要私有实例目录

到当前阶段，`rtnn` 已经不是 demo 仓库，而是正式模板源码主线。但模板若要进入真实部署和长期维护，仅有“模板仓库 + 部署仓库”还不够，仍然缺一个明确的真实下游实例承接层。

如果没有这层，下列问题会持续存在：

1. 模板是否真的能被派生、同步、发布，只能靠口头假设。
2. 服务器契约、实例身份、环境结构配置没有稳定归属。
3. `rtnn-deploy` 会被迫承担“实例配置仓库”的角色，进而和部署引擎耦合。
4. 模板维护者无法用一个真实实例持续验证“模板升级是否仍可消费”。

因此，需要一个私有实例目录来承接真实测试和真实部署相关的实例差异。

## 2. 三仓职责

### 2.1 `rtnn`

`rtnn` 是唯一模板源码主线，负责：

- `backend / admin / app / weapp` 的正式模板代码。
- `backend` 作为接口、权限、OpenAPI、shared contract、SDK 的唯一事实源。
- 模板初始化参数与重写能力。
- 模板发布候选 gate、镜像构建与模板维护文档。

`rtnn` 不负责：

- 真实实例的品牌、域名、目录布局。
- 真实部署实例的服务器契约。
- 真实环境的 secrets。
- 某个实例特有的页面微调、文案覆写、资源文件。

### 2.2 私有实例目录

私有实例目录负责：

- 承接 `rtnn` 的模板代码同步结果。
- 维护实例身份参数与实例级非敏感配置。
- 维护仅对当前实例有效的服务器契约与测试资料。
- 作为模板升级后的持续验收实例。

私有实例目录不应被定义为：

- 第二条模板源码主线。
- 先做功能、再反向搬回模板的试验田。
- 放真实 secrets、真实 SSH 凭据、真实数据库密码的仓库。

### 2.3 `rtnn-deploy`

`rtnn-deploy` 是通用部署引擎，负责：

- server contract schema、渲染模板、校验脚本。
- compose / nginx / runtime env 生成逻辑。
- deploy / rollback workflow 与发布脚本。
- 消费实例仓库提供的非敏感契约文件与 GitHub Environment secrets。

`rtnn-deploy` 不负责：

- 成为真实实例配置唯一归属。
- 复制 `rtnn` 的应用源码。
- 直接维护某个实例的业务级差异文件。

## 3. 唯一事实源

三仓模型下，唯一事实源必须固定：

- 模板源码事实源：`rtnn`
- 实例身份与实例级非敏感契约事实源：私有实例目录
- 部署规则与渲染引擎事实源：`rtnn-deploy`
- 真实环境 secrets 事实源：GitHub Environment secrets 或服务器本地受限 env 文件

这样可以避免：

- 模板仓库和实例仓库都维护一套应用主线。
- 实例仓库和部署仓库都维护一套服务器契约。
- 公开仓库误入真实敏感值。

## 4. 私有实例目录的边界

### 4.1 允许保留的内容

私有实例目录允许保留：

- 项目标识、品牌名、cookie 前缀等实例身份。
- 实例级公开文档与验收说明。
- 非敏感服务器契约，例如域名、网络模式、目录布局、PG/Redis 复用策略。
- 少量实例资源，例如 logo、favicon、截图。
- `.rtnn/*` 这类实例元数据目录。

### 4.2 不允许保留的内容

私有实例目录不允许保留：

- 真正的敏感 secrets。
- 只在 demo 仓库出现、模板仓库没有承接的功能主线。
- 对 `backend` 契约的平行定义。
- 大量不准备回流的页面、模块、脚本。

## 5. 同步策略

私有实例目录不应手工复制 `rtnn` 代码，而应明确采用“上游同步 + 保留实例差异”的模式。

建议在私有实例目录中固定一个同步清单，例如：

- `.rtnn/project.yaml`
- `.rtnn/server-profile.yaml`
- `.rtnn/sync-manifest.yaml`

其中：

- `project.yaml`：实例身份参数。
- `server-profile.yaml`：实例的非敏感服务器契约。
- `sync-manifest.yaml`：哪些路径来自 `rtnn`，哪些路径需要在同步时保留。

同步规则建议固定为：

1. 功能变更先进入 `rtnn`。
2. 私有实例目录通过同步机制拉取 `rtnn` 的正式主线。
3. 私有实例目录只保留实例差异和实例元数据。

## 6. 当前阶段推荐的实例元数据文件

建议私有实例目录首发提供以下文件：

### 6.1 `.rtnn/project.yaml`

负责实例身份，例如：

- `project_id`
- `brand_name`
- `cookie_prefix`
- `image_name_prefix`
- `deploy_application`
- `deploy_event_type`

### 6.2 `.rtnn/server-profile.yaml`

负责实例的非敏感服务器契约，例如：

- 域名与入口模式
- 复用既有共享网络还是独立网络
- PostgreSQL / Redis 是复用还是独立
- 目录布局
- runner 是否启用

### 6.3 `.rtnn/sync-manifest.yaml`

负责同步保留规则，例如：

- 上游仓库和 ref
- 实例需要保留的目录
- 不参与同步覆盖的文件

## 7. 与 `server/` 现状目录的关系

当前本地 `server/` 目录更像是一份现网服务器的运行现状总结，不是正式工程事实源。

后续推荐关系应为：

- `server/README.md`：只作为过渡期现状参考。
- 私有实例目录中的 `.rtnn/server-profile.yaml`：成为实例级服务器契约事实源。
- `rtnn-deploy`：消费该契约并生成部署产物。

## 8. 验收标准

当三仓模型落地后，应达到以下标准：

1. `rtnn` 改动模板能力后，可以明确同步到 `rtnn-demo`。
2. 私有实例目录中的实例身份与服务器契约不再靠口头维护。
3. `rtnn-deploy` 可消费私有实例目录的契约文件，而不是手工抄写环境结构。
4. 公开仓库中不出现真实 secrets。
5. 私有实例目录不演化为第二条模板功能主线。
